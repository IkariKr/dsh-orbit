## Objective and frozen scope

The objective is the **unified Devices and Nodes operator view** — the one
roadmap 0.6 SHOULD line that v0.6 and v0.10 did not deliver: browser-session
visibility, per-node session/connection indicators, explicit target scope, and
mobile-friendly selector/session navigation, per the device-vs-node UX
direction recorded in `docs/ux/dsh-remote-mobile.md`. The frozen MUST/SHOULD/
OUT scope is in the JSON record; highlights:

- **MUST** expose an operator session list (`GET /hub/sessions`, management
  surface, session-gated) built on the existing `browser_sessions` store, and
  explicit revocation (`POST /hub/sessions/revoke`) through the existing
  admission chain with CSRF and single-target validation. No new credentials,
  no new session type.
- **MUST** surface per-node connection indicators (`activeFlows` from the
  existing `MultiNodeFlowTracker`) in the selector read model — a read-model
  enrichment through the already-allowed `GET /hub/selector/nodes` tuple; the
  selector-apex allowlist is **not** extended.
- **MUST** keep indicator wording honest: hub-routed flows and reverse
  presence, never node-local DSH login state (RFC-0011 D4).
- **MUST** make the target route authority explicitly visible on every
  selector card before navigation, and keep failure surfaces
  target-preserving (no automatic retargeting).
- **MUST** make the selector mobile-friendly (responsive, touch-safe) with
  real-phone acceptance as a mounted matrix requirement.
- **MUST NOT** introduce a global active node, cross-node session migration,
  implicit broadcast, or automatic retargeting after failure; **MUST NOT**
  widen the v0.10 edge exemption or alter the selector-apex allowlist;
  **MUST NOT** capture new device-identifying data.
