Sanitized record of the fourth-round review remediation (the terminal/PTTY remediation), the re-acceptance rehearsal, the production promotion, and the Stage 7 manual acceptance. Host names, addresses, credentials, and site-specific paths are withheld; the downstream deployment retains the full evidence in its private state.

## Review remediation in this release

- **Remote PTY via the authenticated proxy path only**: a new profile-local compatibility patch (`src/plugin-patch-dsh-ssh.mjs`) extends the `@linxin666/dsh-ssh` loopback-only fence with the same authenticated-proxy admission as the connection patch. The patch is version-pinned (`0.3.2` by default), uses exact source matching (one helper anchor and exactly three gate endpoints; any missing or duplicated fragment fails closed, as does any unverified bundle), and is enabled through `DSH_ORBIT_PATCH_DSH_SSH=1` (propagated into the candidate container by the runner).
- Security properties preserved and regression-tested: loopback requests keep their original path and are always allowed; remote PTY admission requires the exact public host, HTTPS forwarding, the gateway-injected internal proxy secret, a same-origin context, and a non-cross-site fetch site; unauthenticated, invalid-credential, wrong-host, wrong-origin, and cross-site requests remain denied; the proxy secret is never exposed to the browser; upstream source drift fails closed.
- **Automated terminal check**: the verification sequence now runs a live terminal authorization smoke (`npm run smoke:terminal`) — positive control plus five denial cases against the terminal upgrade endpoint — and a failed terminal gate blocks promotion eligibility.
