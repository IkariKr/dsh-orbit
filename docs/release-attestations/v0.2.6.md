# Release attestation — v0.2.6

Sanitized record of the sixth-round review closure: the strict dsh-ssh verifier now covers the helper's security logic body itself, and the documentation items are aligned. Host names, addresses, credentials, and site-specific paths are withheld; the downstream deployment retains the full evidence in its private state.

## Review closure in this release

- **Full helper security body verification (P1)**: `verifyPatchedLayout()` now constructs the expected helper via the same `buildDshSshHelper({ publicHost, proxyAuthFile })` used to patch, and requires the complete block to appear exactly once, byte for byte. Removing or weakening any security predicate — the HTTPS-forwarding check, the gateway-injected proxy-secret comparison, the `Sec-Fetch-Site: cross-site` rejection, the same-origin check, or the public-host check — fails closed. Five tamper regressions cover each predicate, on top of the existing partial-patch, missing-gate, duplicated-helper, idempotent-re-patch, and constant-mismatch cases. Both `patchDshSshPlugin()` (including its idempotent path) and `verifyDshSshPlugin()` use the same full check.
- **Documentation closure (P2)**: `docs/upgrade.md` describes the v0.2.5 split (`terminalFence` automated authorization evidence vs `terminalPtty` actual PTY runtime evidence from the Stage 7 manual acceptance, with an explicit warning that a fence pass alone is not `terminal.pty` capability evidence); the CLI usage lists the `DSH_ORBIT_PATCH_DSH_SSH` enable flag alongside the plugin root/version variables; `UPGRADE_CHECK_ORDER` now matches the real verification sequence including `terminalFence`.
