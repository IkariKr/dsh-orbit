## Fresh and migration installs

The Stage 7 evidence records a fresh install using an empty Registry database
with schema version `3`, WAL mode, `PRAGMA integrity_check = ok`, and zero
foreign-key violations. It records file-backed v1 → v3 and v2 → v3 migration, v3 validated
no-op reopen, schema shape validation, row/state preservation, and idempotent
reopen. Existing malformed or corrupt inputs are rejected before migration or
WAL mutation; the original bytes remain unchanged and no database is rebuilt or
overwritten.

## Backup and restore

The Registry backup method is `sqlite-vacuum-into`. The evidence records a
standalone image, integrity/FK inspection, source mutation after backup,
writer-quiesced staged restore, atomic publication, WAL/SHM quarantine, and
post-restore state verification. The backup image uses DELETE journal mode while
the active Registry uses WAL; active `.db` files are not copied alone.

Orbit reserves the temporary backup path exclusively before SQLite writes and
uses POSIX mode `0600` at creation, retaining final mode enforcement. The
regression observes the populated temporary image at the
`afterVacuumBeforeChmod` boundary on POSIX. POSIX mode-bit assertions are
skipped in this Windows verification environment; that is recorded as a
platform limitation rather than a pass. The generic DSH snapshot/rollback
contract remains separate.

## Known limitations

The known limitations are recorded exactly as observed in this environment:

- POSIX permission-bit assertions are skipped on Windows; platform ACLs remain
  the Windows control.
- GNU tar behavior for Windows paths is environment-skipped.
- Local Docker repository digests may be unavailable; immutable image IDs are
  recorded where they are the available identity.
- `longLivedTransport`, `terminalFence`, and `terminalPtty` remain `not_run`
  unless a fresh run observes them; they were not converted to pass here.
- The legacy third-party terminal fence and related DSH SSH compatibility debt
  remain freeze-only. Orbit supports DSH core and maintains no third-party
  plugin ecosystem compatibility.
- The final release tag, published release, and production promotion are
  outside this candidate and require final review after Stage 8.
