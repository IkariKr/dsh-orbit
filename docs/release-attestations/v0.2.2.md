# Release attestation — v0.2.2

Sanitized record of the second-round review remediation, the re-acceptance rehearsal, and the production promotion. Host names, addresses, credentials, and site-specific paths are withheld; the downstream deployment retains the full evidence in its private state.

## Review remediation in this release

- **Candidate endpoint identity binding (P0)**: the runner generates a per-run self-signed gateway identity certificate (SAN matching the candidate endpoint host) and mounts it into the candidate gateway in place of the base certificate. Before any check runs, the runner opens a TLS connection to `DSH_SMOKE_URL` and requires the presented certificate fingerprint to equal the per-run identity fingerprint. This closes the false-positive path where smoke tests could run against an unrelated healthy deployment; the verified chain is resolved Compose → running container (candidate token) → candidate gateway → `DSH_SMOKE_URL`.
- **Loopback bind address (P1)**: the resolved compose configuration must publish the candidate port on `127.0.0.1` or `::1`; `0.0.0.0`, `::`, and all-interface bindings fail closed.
- **`candidateDshVersion` manifest binding (P2)**: when the snapshot request carries a candidate DSH version, the manifest must record exactly that value.
- The runner's own HTTP checks trust the per-run identity certificate via its CA content, and the smoke suites receive the same trust through `NODE_EXTRA_CA_CERTS`.
- RFC 0003 was cleaned for consistency: the per-node Hub service identity decision is reflected in the proposal, and the registry machine API versus browser management API boundary is spelled out (the shared element is the fail-closed live smoke methodology, not browser header requirements on machine traffic).
