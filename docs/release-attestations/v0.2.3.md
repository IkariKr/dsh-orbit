# Release attestation — v0.2.3

Sanitized record of the third-round review remediation, the re-acceptance rehearsal (candidate and verify), and the production promotion. Host names, addresses, credentials, and site-specific paths are withheld; the downstream deployment retains the full evidence in its private state.

## Review remediation in this release

- **Gateway certificate targets (P1)**: the runner's default gateway identity targets now match the public example compose exactly (`/run/certs/fullchain.pem` and `/run/certs/privkey.pem`, service `caddy`), the three tuning variables (`DSH_UPGRADE_GATEWAY_SERVICE`, `DSH_UPGRADE_GATEWAY_CERT_TARGET`, `DSH_UPGRADE_GATEWAY_KEY_TARGET`) are documented, and the resolved base compose must already mount a certificate at the configured targets — a misconfigured target fails closed before the build. A regression test reads the repository's real `docker/compose.example.yaml` so the runner defaults cannot drift from the public example again.
- **Verify CA propagation (P1-2)**: the `verify` path reads the per-run identity certificate from the workdir and passes both its path and content into the verification sequence, so runner HTTPS checks and the smoke suites trust the per-run certificate without any manual `NODE_EXTRA_CA_CERTS`. Regression-tested end to end (local HTTPS gateway presenting the per-run certificate, real smoke child processes, and the full CLI wiring).

## Stage 7 manual acceptance evidence

Recorded against the production deployment pattern (browser session through the authenticated gateway, plus in-container checks):

- **Long-lived transport / live agent traffic**: the web UI loads and operates normally through the authenticated gateway; during the active browser session the DSH container's network namespace showed multiple ESTABLISHED long-lived connections to the DSH web listener (8 toward DSH, 22 total), i.e. the UI/agent transport is functional end to end.
- **Sidebar terminal panel**: the sidebar SSH panel opens on production and the terminal tab is selectable (panel opens; entry appears in the UI).
- **Terminal PTY spawn and `dsh --version`**: through the gateway, PTY spawn is refused by the `@linxin666/dsh-ssh` plugin's deliberate loopback-only fence (`forbidden: loopback-only`); this is a recorded design limitation with an approved remediation (reviewed extension patch, pending implementation), not a regression. `dsh --version` succeeds in the container and the persisted profile's `node-pty` binding is healthy.

The compatibility report therefore keeps both checks `not_run` with the annotation that the long-lived transport was manually verified during Stage 7 acceptance and that terminal PTY evidence is recorded in this attestation.
