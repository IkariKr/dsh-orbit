# v0.3 Stage 7 operational hardening

This document records the Stage 7 operational-hardening candidate. It is
separate from the Stage 6 mounted Gate B attestation and does not authorize
Stage 8.

## Scope

The candidate covers only the SOP Stage 7 scope:

- fresh file-backed Registry installation and startup maintenance;
- real file-backed v1 → current, v2 → current, and v3 → current migration;
- SQLite-consistent backup → mutation → restore;
- fail-closed unsupported, malformed, and corrupt database handling;
- persistent-state inspection, integrity checks, and restart seams;
- operational retention and recovery evidence where recorded by the Stage 7 drill.

No wire protocol, authentication/trust model, Node identity semantics, schema
contract, routing, reverse connection, fleet, terminal, or third-party plugin
scope was added.

## Implementation

- SQLite schema validation and startup classification: `src/registry/sqlite.mjs`
- SQLite operational backup/restore: `src/registry/backup.mjs`
- Hub startup fail-closed boundary: `bin/dsh-orbit-hub.mjs`
- Isolated operational drill: `scripts/registry-stage7-drill.mjs`
- Regression coverage: `test/registry-backup.test.mjs`,
  `test/registry-stage7-contract.test.mjs`, and `test/hub-cli.test.mjs`

The backup method is `VACUUM INTO` on the running WAL-backed connection. The
result is validated as a standalone SQLite image with `integrity_check`,
`foreign_key_check`, schema validation, row counts, and a deterministic
non-secret business-state digest. Restore validates the standalone image,
stages it, atomically publishes it only after the Hub connection is closed,
and quarantines the replaced database and any stale `-wal`/`-shm` sidecars.
A live `.db` copy is never treated as a consistent backup.

## Local executable evidence

The dedicated drill writes raw, sanitized evidence to:

```text
data/stage7-drill-evidence.json
```

Run it with:

```text
npm run stage7:drill
```

The drill uses a fresh temporary root per invocation and records the exact
commit, branch, Node runtime, schema version, unchanged production health and
retention thresholds, migration pre/post state, backup/mutation/restore state,
WAL/SHM handling, and cleanup. It intentionally does not consume or overwrite
Stage 6 raw evidence.
