## Topology exercised (loopback deployment; config == docs)

```text
Operator browser --TLS--> Gateway (basic-auth gate + strip/inject) --> Hub :5445
Node A / Node B ------------------------------- private machine path --> Hub :5445
```

The gateway (Caddy-equivalent in the E2E) terminates TLS with a real
certificate, runs an authentication gate FIRST, strips client-supplied
assertion/principal headers, injects them only after authentication,
passes the browser's Cookie / Origin / Sec-Fetch-Site through, and
refuses `/api/v1/*` with 403. The Hub listens on loopback only and its
listener policy is unchanged.

## Scenario results

| Step | Result |
| --- | --- |
| unauthenticated gateway request | 401 gateway-auth-required (never reaches the Hub) |
| forged internal assertion/principal | stripped; the Hub saw only injected values |
| session bootstrap through TLS gateway | 200; principal `operator`; cookie + CSRF issued |
| browser Cookie/Origin/Sec-Fetch-Site pass-through | verified at the Hub (origin === gateway baseUrl) |
| `/api/v1/*` via the gateway | 403 machine-ingress-denied |
| Node A + Node B enroll (machine path) | both `fresh`; reports uploaded; capabilities derived |
| gateway restart drill | browser path down → Hub + both nodes untouched → new session works |
| A network outage + clock advance | A `stale` (4 min) → `lost` + `contact-lost` (24h); B stays `fresh` throughout |
| A reconnect | `fresh`, alert cleared |
| Hub restart (same port, persistent SQLite DB) | both identities survive; clock re-bound |
| delete A | A heartbeat denied → REVOKED; B `fresh` |
| reenroll A | same nodeId + new key; B `fresh`; both nodes active again |

### Persistence checks

- Registry DB is a real file (WAL); the Hub restart step reopens it and
  identities, keys, health and events survive.
- Node state files survive process-level restarts (`recoverAfterRestart`),
  including a Hub restart mid-lifecycle.

## How to reproduce

Requires OpenSSL on PATH (self-signed certificate generation for the TLS
gateway). No external services; no third-party plugins; no v0.4/v0.5 scope.

## Known limitations carried into Stage 7

- The E2E runs on loopback; a mounted-deployment drill (real NAS, real
  Caddy, real DSH containers) is part of the Stage 7/8 evidence along with
  backup/restore, schema migration and corruption drills.
- The gateway example uses basic_auth as the authentication gate; any
  gateway that satisfies "authenticate first, then strip+inject, keep
  browser headers" is acceptable.
