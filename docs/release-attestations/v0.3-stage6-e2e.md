## Gate B disposition

The `629c97c` mounted run is valuable positive evidence, but final review found
three issues that prevent using it as the final Gate B attestation:

1. maintenance could make `registryContact` healthier when the drill contact
   clock moved backwards on reset, allowing `lost -> fresh` before a real
   heartbeat; maintenance is being corrected to aging-only semantics;
2. the private machine ingress parsed request targets with WHATWG `URL`, which
   can canonicalize dot segments before its allowlist; the ingress is being
   corrected to exact raw request-target matching;
3. image provenance was captured from mutable image tags before the compose
   `--build`, so recorded IDs could describe a prior local build rather than
   the containers actually exercised; the driver is being corrected to
   inspect the running container image IDs after startup.

The remediation also adds a mounted assertion that, after accelerated aging is
reset, A remains `lost` across a real maintenance tick until its authenticated
heartbeat arrives. A new clean candidate must rerun the full trusted-browser,
real-DSH, two-node mounted lifecycle and replace/supersede this evidence before
Review Gate B can be approved.

Stage 7, backup/restore work, v0.4/v0.5 routing, reverse connections,
multi-node sessions, fleet execution, and third-party plugin expansion were not
started.
