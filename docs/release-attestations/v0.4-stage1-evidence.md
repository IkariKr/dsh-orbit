## 3. Schema Changes and Migration

- `SCHEMA_VERSION`: 3 → 4
- `nodes.reachable`: CHECK constraint relaxed from `(reachable = 'unknown')` to `(reachable IN ('unknown', 'ok', 'unreachable'))`. Existing and migrated nodes remain `reachable = 'unknown'`.
- New table `route_targets`:
  ```sql
  CREATE TABLE route_targets (
    node_id TEXT PRIMARY KEY REFERENCES nodes(node_id),
    route_target_origin TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
  )
  ```
- Migration step 3 recreates `nodes` table with the expanded `reachable` domain and creates `route_targets`. Data in `nodes`, `node_keys`, `reports`, `audit`, `events`, `browser_sessions` remains fully intact.
- Foreign key pragma is toggled off during table recreation and re-enabled in a `finally` block before post-migration integrity checks run.

## 4. API and UI Changes

- `GET /hub/nodes/:nodeId/route-target`: returns `{ nodeId, routeTarget }` (or 404 if node not found)
- `PUT /hub/nodes/:nodeId/route-target`: sets or replaces the single active route target for the node
- `DELETE /hub/nodes/:nodeId/route-target`: removes the active route target
- Unsupported methods/actions (e.g. `POST`, `PATCH`, `/set`, `/remove`) fail closed with 404/405 without mutating state or creating audit records.
- Operator UI: node detail view displays current target, input field for origin, Save button, Remove button (when configured), and banner for validation errors. Tombstoned nodes render route target as read-only with mutation controls disabled.

## 5. Audit Logging

- `hub.route-targets.create`: recorded when initial target is set
- `hub.route-targets.replace`: recorded when target is updated
- `hub.route-targets.remove`: recorded when target is deleted
- Audit records contain: actor (operator principal), nodeId, target origin metadata, timestamp. Sensitive headers, CSRF tokens, and credentials are never logged.
