## Review closure in this release

- **Terminal smoke gating (P1)**: the live terminal fence smoke runs only when the dsh-ssh patch is enabled (`DSH_ORBIT_PATCH_DSH_SSH=1`). Disabled deployments report `terminalFence: not_run` and do not run the smoke; enabled deployments run it and a failed fence blocks promotion eligibility. Two regression tests cover both paths.
- **Strict patched-bundle verification (P1)**: the verifier now requires exactly one helper declaration, exactly three patched gates, zero remaining unpatched gates, the exact configured public host and proxy auth file constants, and an exact plugin version match. The idempotent re-patch path runs the full verifier instead of trusting the marker. Regression tests cover partial patches, tampered helpers, duplicated helpers, missing gates, and mismatched auth-file constants. Live evidence: the production bundle (patched under v0.2.4) passed the strict verifier at startup (`dsh-ssh: ok`).
- **Fence vs PTY evidence split (P1)**: the report now distinguishes `terminalFence` (the automated 6/6 live authorization smoke) from `terminalPtty` (recorded `not_run`; actual PTY runtime evidence comes from the Stage 7 manual acceptance recorded in the attestation). Future fleet capability advertisement must not treat the fence result alone as `terminal.pty` runtime evidence.
- **Plugin configuration propagation (P2)**: `DSH_SSH_PLUGIN_ROOT` and `DSH_SSH_PLUGIN_VERSION` are part of the upgrade configuration, are propagated into the candidate container through the compose override when the patch is enabled, and are listed in the CLI usage and README.
