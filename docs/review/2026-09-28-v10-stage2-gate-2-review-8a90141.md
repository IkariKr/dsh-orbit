## Findings (P3 ×4) and disposition (converged before Stage 3)

1. **Scrub-before-verify order was not mechanically pinned** (a mutant that
   verifies first passed the suite). **Fixed**: the stub now records a call
   order; the happy path asserts `order[0] === "scrub"` and that the scrub
   actually clears the address bar.
2. **The `replaceState` stub did not clear `location.search`**, so the
   "retry keeps the in-memory token" semantics were not really constrained.
   **Fixed**: the stub mirrors the real side effect (search cleared on
   `/auth`), and the retry test now asserts the search is empty before the
   retry — a re-read of the URL would yield nothing.
3. **Rendered-content provenance unpinned** (a mutant interpolating server
   error messages into the DOM passed) and the `verifying` in-flight state
   was never asserted. **Fixed**: every rendered fragment must match the
   fixed-template shape (`data-state` ∈ the six states), asserted across the
   happy path, failure mappings, retry, and missing-state tests; the happy
   path now holds the fetch pending and asserts `verifying` in flight.
4. **The `missing` state was undocumented** in the RFC/SOP state
   enumerations. **Fixed**: both now enumerate `missing` (the A1 no-query
   landing and grammar-violating queries).
