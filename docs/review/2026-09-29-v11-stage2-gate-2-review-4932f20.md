## Findings (P3 ×3) and disposition (converged in the follow-up commit)

1. **"Silent refresh" not actually pinned** — a regression to
   `fetchNodes()`-per-tick (loading flicker every 30s) would pass the suite.
   **Fixed**: the happy-path test now holds the fetch pending and asserts the
   in-flight banner stays free of the loading state during polls.
2. **Poll-failure banner is a second implementation without the Retry
   button** that the manual-path failure renders. **Fixed**: poll failures
   reuse the manual path's rendering contract (Retry affordance included) via
   a shared banner renderer.
3. **Every successful poll rebuilt the list DOM unconditionally**, resetting
   keyboard focus every 30s. **Fixed**: the poll serializes the node list and
   skips the re-render (and the banner clear) when nothing changed, so focus
   survives idle polls.
