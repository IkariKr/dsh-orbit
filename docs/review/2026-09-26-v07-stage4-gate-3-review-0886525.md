## Detailed Review Against Acceptance Criteria

### 1. Outage Containment (M28 Field 17 `targetNodeOutageDuringJobExecution`)

- **Node Crash Isolation**:
  - In `src/registry/fleet-scheduler.mjs`, each target node task is dispatched inside an independent worker loop via `dispatchWithTimeout()`.
  - In the event of network disruption, `ECONNRESET`, daemon crashes, or unhandled exceptions thrown by transport dispatch, the catch block (`lines 575-585`) cleanly traps the error, records `nodeTask.status = "failed"`, and captures the exact error code (e.g. `ECONNRESET`) and message on `nodeTask.error`.
  - Peer worker tasks on sibling nodes continue executing concurrently without interruption or delay.
  - Overall job status evaluates to `"partial"` when at least one node succeeds and at least one node fails or times out (`lines 609-610`).
- **Accounting Invariant & Result Completeness**:
  - `FleetJobScheduler.executeJob()` enforces the reconciliation invariant (`lines 613-629`):
    `computedTotal === job.summary.totalTargets` where:
    `computedTotal = completed + failed + skipped + timeout + unreachable`.
  - Also strictly enforces `Object.keys(job.results).length === job.summary.totalTargets`.
  - Any invariant deviation throws immediately and marks the job failed.
  - Verified by Test 1 (`outage containment: target node crash during execution marks target failed while peers complete`).

### 2. Reverse Node Disconnect & Capacity Handling (M28 Field 18 `reverseNodeDisconnectDuringJobExecution`)

- **State Diagnostics & Error Classification**:
  - `src/registry/fleet-scheduler.mjs:703-745` inspects `this.reverseSessions` and `this.reverseChannels`:
    1. If `reverseSessions.getSessionInfo(nodeId)` returns `null`, the node is marked `status: "unreachable"` with code `reverse-session-offline`.
    2. If session exists but `sessionInfo.routeReady !== true`, marked `status: "unreachable"` with code `reverse-route-unreachable`.
    3. If `reverseChannels.hasChannelForSession(nodeId, sessionId)` is false or channel manager is unavailable, marked `status: "unreachable"` with code `reverse-capacity`.
  - Nodes failing these pre-dispatch checks do not trigger panics or abort sibling tasks.
- **Payload Size Bound**:
  - RFC-0014 D3.4 stipulates that reverse task payloads must not exceed 32 KiB because the underlying WebSocket frame limit is 64 KiB.
  - Evaluated via `Buffer.byteLength(JSON.stringify(job.payload ?? {})) > 32 * 1024`.
  - When exceeded, returns `status: "failed"` with code `payload-too-large` before any dispatch attempt.
  - Verified by Test 2 (`reverse node outage: disconnect, capacity wait, and payload size bounds`).

### 3. Zero Cross-Node Credential Leakage (M28 Field 27 `zeroCrossNodeCredentialLeakInJob`)

- **Payload & Snapshot Deep Isolation**:
  - In `submitJob()` (`lines 326-339`), incoming payloads are deeply validated and cloned via `JSON.parse(JSON.stringify(payload))` to break reference links to caller state.
  - In `getJob()` (`lines 414-430`), `safeClone(job.payload)` and `safeClone(job.results)` are executed prior to credential scrubbing.
  - External inspection by operators receives thoroughly scrubbed data via `scrubSensitiveCredentials()` and `scrubString()`.
- **Log and Output Scrubbing**:
  - `scrubString()` (`lines 111-141`) redacts:
    - Private key blocks (`[REDACTED_PRIVATE_KEY]`)
    - URL embedded passwords (`http://user:[REDACTED]@host`)
    - Bearer tokens (`Authorization: Bearer [REDACTED_TOKEN]`)
    - Basic auth credentials (`Authorization: Basic [REDACTED_AUTH]`)
    - Generic authorization headers (`Authorization: [REDACTED]`)
    - `curl -u user:pass` invocations (`curl -u user:[REDACTED]`)
    - Session identifiers and cookies (`dsh-orbit-hub-session=[REDACTED_SESSION]`, `sess_<hex>`)
    - Key-value credentials across common token/secret/password/api-key patterns.
  - In `src/registry/registry.mjs:472`, `queryAudit()` processes audit details through `sanitizeAuditDetail()`, preventing secret leakage into audit trail views.
  - Verified by Test 3 (`zero credential leakage: cross-node payload isolation and log scrubbing`).

### 4. Concurrent Fleet Job Execution (M28 Field 12 `concurrentFleetJobExecution`)

- **Independent Concurrency Pools**:
  - Concurrency is bounded per-job by `Math.min(this.maxConcurrentDispatches, eligibleNodes.length)`, avoiding starvation or runaway thread exhaustion.
  - Multiple fleet jobs with overlapping or distinct target nodes run concurrently without shared mutable mutexes or deadlocks.
  - Each job possesses its own isolated `_abortController` and `_executionPromise`.
- **Cancellation Isolation**:
  - Cancelling Job A via `cancelJob(jobId)` triggers only Job A's `_abortController.abort()`.
  - Active worker loops on sibling job instances listen solely to their own abort signals.
  - Cancellation of Job A does not alter, interrupt, or corrupt concurrent Job B.
  - Verified by Test 4 (`concurrency: multiple concurrent fleet jobs execute without cross-job interference`).
