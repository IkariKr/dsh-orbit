### 2.3 Detailed Invariant & Code Verification

#### A. Schedule Parser (`src/registry/schedule-parser.mjs`)
- **5-Field Syntax**: Parses standard `minute (0-59)`, `hour (0-23)`, `day-of-month (1-31)`, `month (1-12)`, and `day-of-week (0-7, 0/7=Sun)`.
- **Sunday 0 and 7**: Normalizes 7 to 0 per standard cron conventions.
- **Bounds Checking**: Rejects out-of-range minutes (`60`), hours (`25`), days (`32`), months (`13`), and weekdays (`8`). Rejects non-integer steps (`*/0`, floats).
- **Timezone Safety**: Strictly uses UTC methods (`getUTCMinutes`, `getUTCHours`, `getUTCDate`, `getUTCMonth`, `getUTCFullYear`, `toISOString`) to eliminate any DST or local timezone drift.
- **Search Termination**: Calculates next strictly future run date bounded to a 5-year maximum search window, preventing infinite loops on impossible dates (e.g. `0 0 30 2 *` for Feb 30 throws `cron-unreachable`).

#### B. Scheduled Workflow Engine (`src/registry/schedule-engine.mjs`)
- **Target Safety & Wildcard Prohibition**:
  - `validateTarget()` explicitly checks for bare wildcards (`"*"`, `{ mode: "all" }`, `{ mode: "broadcast" }`, `{ nodeIds: "*" }`) and throws `wildcard-prohibited`.
  - Rejects empty target sets (`{ mode: "explicit", nodeIds: [] }`).
  - Requires valid capability strings (`{ mode: "capability", capability: "..." }`).
- **Credential Scrubbing**:
  - `hydrateScheduleRow()` invokes `scrubSensitiveCredentials(JSON.parse(row.payload_json || "{}"))`.
  - Scrubbing strips/redacts sensitive keys (tokens, passwords, keys) from returned objects and audit records.
- **Foreign Key Safety**:
  - `fleet_schedule_runs.job_id` is defined as `job_id TEXT` without referencing the non-existent `fleet_jobs` table, resolving the Stage 0 Gate A P3 finding and preventing SQLite `PRAGMA foreign_key_check` failures.
- **Concurrency & Re-entrancy**:
  - `concurrencyPolicy: "forbid"` checks in-flight jobs in `FleetJobScheduler` via `_fleetScheduleId`. If a prior run is still pending or running, the due run is skipped with code `concurrency-forbid` and recorded in `fleet_schedule_runs`.
  - `evaluateDueSchedules()` uses `_evaluating` re-entrancy lock to prevent overlapping evaluation ticks.
- **Missed-Run Recovery on Startup**:
  - `reconcileOnStartup()` queries active due schedules. If `missedRunPolicy === "run-once"`, it dispatches one immediate catch-up run. If `missedRunPolicy === "skip"`, it calculates the next future occurrence.

## 3. Findings

### [P3] Cron parser tolerates trailing dashes or leading hyphens via numeric coercion

- **Location**: `src/registry/schedule-parser.mjs:51-57`
- **Description**:
  When parsing ranges such as `-3` or `-`, splitting by `-` yields an empty string for the first element (`bounds[0] === ""`). JavaScript's `Number("")` coerces to `0`, which passes `Number.isInteger(0)`.
  As a result:
  - `-3` is parsed as `0-3` instead of throwing `invalid-cron-range` or `invalid-cron-number`.
  - `-` is parsed as `0-0`.
- **Impact**: Very low; typical cron inputs generated by operators or UI selectors are well-formed strings. However, stricter validation rejecting empty string segments would enhance defensive parsing against malformed inputs.
- **Recommended Action**: In Stage 2 or 4, check that `bounds[0].trim() !== ""` and `bounds[1].trim() !== ""` before numeric conversion in `parseCronField`.

### [P3] SQLite schema migration consolidation for future centralized registry open

- **Location**: `src/registry/schedule-engine.mjs:47-87` vs `src/registry/sqlite.mjs`
- **Description**:
  `ScheduledWorkflowEngine` currently initializes its own tables (`fleet_schedules`, `fleet_schedule_runs`) in `initTables()` via `CREATE TABLE IF NOT EXISTS`.
  In `src/registry/sqlite.mjs`, schema migrations are version-tracked up to `SCHEMA_VERSION = 6` with strict `EXPECTED_TABLE_COLUMNS` and `registrySchemaShape`.
- **Impact**: Non-blocking for Stage 1 engine functionality. When the Hub server integrally boots `ScheduledWorkflowEngine` in Stage 2, either:
  1. Advance `SCHEMA_VERSION` to 7 in `src/registry/sqlite.mjs` and include `fleet_schedules` and `fleet_schedule_runs` in `EXPECTED_TABLE_COLUMNS`, or
  2. Keep schedule persistence cleanly namespaced as an engine-managed extension.
- **Recommended Action**: Plan the schema migration consolidation as part of Stage 2 Hub server endpoint integration.
