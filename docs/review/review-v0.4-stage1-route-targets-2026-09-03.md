## Findings

### P2-1 — Route-target management API accepts contradictory method/action combinations

Location:

- `src/registry/server.mjs`, route-target management matcher and dispatch around the `/hub/nodes/:nodeId/route-target` routes.

Current route matching accepts an optional `/set` or `/remove` suffix, but mutation is primarily selected from the HTTP method rather than from a strict method/path contract.

Independent live reproduction:

```text
PUT /hub/nodes/<nodeId>/route-target/remove
body: { "routeTarget": "https://unexpected-set.example" }
```

Actual result:

- HTTP 200
- route target is **created/replaced** with `https://unexpected-set.example`

And:

```text
DELETE /hub/nodes/<nodeId>/route-target/set
```

Actual result:

- HTTP 200
- route target is **removed**

Therefore the current API allows:

```text
/remove + PUT    → SET
/set    + DELETE → REMOVE
```

This is not an authentication bypass, because a valid operator session and CSRF token are still required. It is nevertheless a fail-closed contract defect on a state-changing management surface: an unsupported or contradictory route should return 404/405 and must not mutate state.

Recommended remediation:

Prefer the smaller API surface:

```text
GET    /hub/nodes/:nodeId/route-target
PUT    /hub/nodes/:nodeId/route-target
DELETE /hub/nodes/:nodeId/route-target
```

Remove `/set`, `/remove`, and generic POST aliases unless there is a concrete compatibility requirement for them.

Required negative tests:

- every unsupported method/path combination returns 404/405;
- Registry route target remains unchanged;
- no route-target mutation audit entry is created.

### P3-1 — Tombstoned nodes still show editable Route Target controls

Backend behavior is safe: `setRouteTarget()` rejects a tombstoned node with `409 node-tombstoned`.

The node-detail UI nevertheless renders the Route Target input and Save button for tombstoned nodes, so the user can attempt a mutation that is guaranteed to fail.

Impact is UX-only; there is no state or authorization bypass.

Suggested cleanup, not a Stage 1 blocker:

- active node: edit/save/remove controls;
- tombstoned node: render route target read-only, or otherwise disable unsupported mutation controls.

Do not expand scope to solve this during the P2 remediation unless the change remains trivial.
