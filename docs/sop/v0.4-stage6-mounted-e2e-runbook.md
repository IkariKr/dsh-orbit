# DSH Orbit v0.4 Stage 6 Mounted E2E Runbook

## 1. Scope and Topology

This runbook defines the operational procedures for executing the DSH Orbit v0.4 Stage 6 Real Two-Node Mounted Product End-to-End Rehearsal.

Topology:
```text
                         Browser / Client
                                │
                        HTTPS + Outer Auth
                                │
                                ▼
                      ┌───────────────────┐
                      │ Rehearsal Gateway │
                      │ selector + *.node │
                      └─────────┬─────────┘
                                │
                           Hub loopback
                                │
                    ┌───────────┴───────────┐
                    │                       │
                    ▼                       ▼
             Node A RouteIngress     Node B RouteIngress
             TLS + Private CA        TLS / Localhost
                    │                       │
                    ▼                       ▼
               Real DSH A              Real DSH B
               NAS class            Workstation class
```

## 2. Invariants & Safety Guarantees

1. **Explicit Selection**: The browser selects an endpoint via the Selector UI, which performs a full navigation to `n-<nodeId>.<routeDomain>`.
2. **Strict Route Isolation**: Traffic for Authority A reaches only Node A / DSH A. Traffic for Authority B reaches only Node B / DSH B. No automatic failover is permitted.
3. **Outer Gateway Authentication**: The wildcard gateway protects selector and node endpoints, strips outer gateway credentials (`x-gateway-auth`, `gateway-auth` cookie), and injects authenticated proxy assertions.
4. **Host-Only Cookie Isolation**: Any parent-domain `Domain=.<routeDomain>` cookie from downstream is stripped by RouteProxy to host-only scope.
5. **Fail Closed**: Any node outage, probe failure, or tombstoning fails closed immediately (503 Service Unavailable / 404 Not Found) with a selector return URL.

## 3. Required Drills & Evidence Sequence

1. **Rehearsal Bring-Up**: Launch Hub with `DSH_ORBIT_HUB_TRUSTED_SCHEME=https`, Gateway on wildcard domain, Node A (private CA TLS) with real DSH A, and Node B with real DSH B.
2. **Eligibility Convergence**: Both nodes satisfy 5-condition routing eligibility (`active`, `routeTarget`, `reachable=ok`, `activeKey`, `web.routes`).
3. **Scenario 1 (Selector Initial Shell)**: Selector shell displays Node A and Node B with active state pills, dimension badges, and green Open buttons.
4. **Scenario 2 (Open Node A)**: Operator opens Node A; browser navigates to Authority A and loads real DSH A (HTTP root, assets, API, and WebSocket).
5. **Scenario 3 (Open Node B in Tab 2 & Tab 1 Isolation)**: Operator opens Node B in Tab 2; Tab 1 remains on Node A without retargeting.
6. **Route Isolation Drill**: Authority A never reaches Node B; Authority B never reaches Node A.
7. **Cookie & Credential Isolation Drill**: Outer gateway credentials and parent-domain cookies do not leak downstream.
8. **Failure Drill A (RouteIngress Outage)**: Stop Node A RouteIngress -> requests fail closed, probe marks unreachable, Selector marks Node A unavailable, Node B unaffected.
9. **Failure Drill B (DSH Down, Ingress Alive)**: Stop real DSH A -> 503 Service Unavailable, probe marks unreachable, Selector marks Node A unavailable, Node B unaffected.
10. **Recovery Drill**: Restore real DSH A -> probe succeeds -> reachable=ok -> Selector restores Open button -> clicking Open succeeds.
11. **Delete Drill**: Operator deletes Node A -> tombstoned, Hub route key revoked, direct bookmark fails closed with 404, Node B unaffected.
12. **Restart Drill**: Hub and Node B restarted -> node IDs, route targets, and authorities remain stable.

## 4. Evidence Directory & Manifest Specifications

Artifacts are placed in `test/evidence/stage6/`:
- `test/evidence/stage6/manifest.json`
- Screenshots for each required scenario
- Attestation: `docs/release-attestations/v0.4-stage6-mounted-e2e.md`

Manifest required fields:
- `schemaVersion: 2` for the structured HOLD/transport semantics introduced by the Stage 6 governance remediation
- `stage`: truthful human-readable Stage 6 evidence scope
- `branch`, `testedCommit`, `timestamp`
- `scope`: `local-multi-process-rehearsal` until the physical two-host rerun exists
- `reviewGate`: `HOLD` while required physical Stage 6 evidence remains incomplete
- `physicalTwoHostE2E`: `NOT_EXECUTED` until the physical two-host rerun is actually performed
- `browser`: `name`, `version`, `engine`, `backend`, `viewport`
- `gateway`: `rehearsalSelectorAuthority`, `trustedExternalScheme`, `tlsState`
- `nodeA` / `nodeB`: `nodeId`, `authority`, `routeTargetClass`, `routeTargetScheme`, `tlsMode`, `tlsVerified`, `dshIdentity`
  - HTTPS route targets must record the applicable TLS mode and `tlsVerified: true` after verification.
  - HTTP route targets must record `tlsMode: "none"` and `tlsVerified: null`; there is no TLS result to claim.
- `scenarios`: array with `id`, `name`, `expected`, `actual`, `result`, and optional `file`, `bytes`, `sha256`
  - `result` is one of `PASS`, `FAIL`, `NOT_EXECUTED`, `BLOCKED`.
  - A required drill that was not run must be `NOT_EXECUTED`, never `PASS` with explanatory prose.
- Zero secrets permitted.
