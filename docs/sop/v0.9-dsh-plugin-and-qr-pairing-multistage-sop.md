### 1.1 Non-Negotiable Architecture Constraints (Stop-Work Invariants)
If implementation discovers that any of the following must change, **STOP** and return to architecture review:

1. **Strict Identity Separation (Operator Session vs DSH Node)**:
   - An authorized browser/mobile client is an **Operator Session** (`sessionToken`), NOT a DSH machine node.
   - A DSH runtime machine is an **Enrolled Node** (`nodeId`, Ed25519 node keypair).
   - Scanning a QR code authorizes an operator session or bootstraps an explicit node enrollment intent; it must NEVER conflate browser sessions with node identities or grant arbitrary node-level machine authority to a browser client.
2. **Prohibition of Virtual Loopback / Host-Origin Spoofing**:
   - The plugin must NEVER rewrite external request `Host`, `Origin`, `Sec-Fetch-Site`, or `socket.remoteAddress` to `127.0.0.1`.
   - DNS Rebinding defense and same-origin / cross-site protections must remain intact. External requests must be properly routed through Orbit's verified gateway boundary.
3. **Transport Security Invariant**:
   - All pairing exchanges, API dispatches, and WebSocket tunnels must operate over verified TLS (standard HTTPS/WSS with valid certificates).
   - The QR code payload URL must strictly use `https://` targeting the Hub's verified TLS route authority (e.g., `https://<hub-domain>/auth?token=...`).
   - Plain HTTP with client-side RSA padding cannot substitute for TLS and is strictly prohibited across untrusted or local networks.
4. **Zero Long-Lived Static Bearer Credentials**:
   - Pairing codes must be ephemeral (5-minute TTL, single-use, immediately destroyed upon verification).
   - Permanent 365-day static bearer tokens or unrevocable URL credentials are strictly prohibited. All sessions must possess bounded TTLs and support immediate revocation.
5. **DSH Integration Boundary (Clean Seam)**:
   - DSH configuration must be stored under the official `~/.dsh/settings.yaml` namespace (`dsh-orbit`) via the DSH `settings` service.
   - DSH UI integration must strictly use official frontend slots (`slots.inject('settings.section')`), without private DOM scraping, fragile CSS class guessing, or monkey-patching DSH core services (`connection`, `browserAuth`, etc.).
6. **M36 Matrix Canonical Extension**:
   - Extends the 32 canonical fields from RFC-0015 (M32) to 36 fields (M36) by adding 4 dedicated plugin & QR pairing fields (17 automated, 19 mounted).

## 2. Global Construction Rules

### 2.1 RFC-First Gate
- Before Gate A: Only documentation, RFC-0016 specifications, M36 acceptance matrix definitions, and governance contract tests may be committed.
- No v0.9 product runtime code under `src/**`, `ui/**`, `bin/**`, or `lib/**` may be committed before Gate A records an explicit **GO** verdict.

### 2.2 DSH Native Plugin Packaging Standards
- The plugin must conform to DSH Cordis packaging standards:
  - `package.json` must declare `"keywords": ["dsh", "dsh-plugin", "cordis-plugin"]`;
  - `package.json` must declare `"dsh": { "bundle": { "patch": "./cordis.patch.yml" }, "client": { "inject": ["@deepseek-ai/dsh-client-ui-settings"], "platform": "web" } }`;
  - Define `cordis.patch.yml` declaring entry insertion (`id: orbit`, `name: dsh-orbit`);
  - Export server-side entry (`.`) and client-side bundle (`./client`);
  - Declare module-level `export const inject = ['webServer', 'settings'];` before `apply(ctx)`.

### 2.3 QR Pairing & Bootstrap Safety Rules
- **Local Generation Only**: The QR code must be rendered as an inline vector `<svg>` entirely in the local client browser (zero external network requests or third-party QR generation APIs).
- **Verified TLS Authority URL**: The URL encoded in the QR code must resolve to the Hub's verified TLS route authority (`https://...`), never raw unencrypted `http://` IP addresses.
- **Single-Use Disposable Codes**: A 6-digit dynamic pairing code must be valid for at most 300 seconds (5 minutes) and must be permanently invalidated immediately upon the first verification attempt.
- **Fail-Closed Brute-Force Defense**: Repeated verification failures must trigger exponential backoff and IP-level 429 lockout.

### 2.4 Evidence Honesty & Baseline Lineage
- `PASS` status requires physical verification and observed execution evidence.
- Every commit must descend in a strict single-parent line from the accepted v0.8 closure `c15ca5865f1519fccbb277f2a440c3b1496e1bb9`.

## 3. Staged Implementation Plan (Stages 0 through 6)

  - Governance contract tests (`test/v09-governance-contract.test.mjs`).
- **Gate A Review**: Independent architecture review by `@code-reviewer2`. P0/P1/P2 must be 0 for GO.

### Stage 1: Cordis Plugin Packaging & Settings Persistence Model (Gate 1)
- **Objective**: Implement the standard Cordis plugin package structure, entry lifecycle (`apply(ctx)`), and bidirectional binding to DSH Settings service (`~/.dsh/settings.yaml`).
- **Scope & Architectural Demarcation**:
  - Plugin metadata: `package.json` DSH exports, `cordis.patch.yml`;
  - Module exports: `export const name = 'dsh-orbit';` and `export const inject = ['webServer', 'settings'];` before `export function apply(ctx)`;
  - Local DSH Node endpoints: `src/plugin/index.mjs` registers local node health/status endpoint `GET /api/orbit/node-status` on DSH Node's `ctx.webServer` (distinct from Hub endpoints);
  - Settings service binding: `bindDshSettings()` reading, watching, and mutating the `dsh-orbit` namespace in `~/.dsh/settings.yaml`;
  - Unit and contract tests for plugin lifecycle and settings persistence.
- **Gate 1 Review**: Independent code review of Stage 1 implementation.

### Stage 2: QR Pairing Protocol, Short-Lived Bootstrap Secret & Hub Endpoints (Gate 2)
- **Objective**: Implement Hub-side QR pairing code generation, 6-digit ephemeral code management, and verification endpoints.
- **Scope & Architectural Demarcation**:
  - `src/registry/pairing-code.mjs`: `generatePairingCode()` producing cryptographically random 6-digit codes with 5-minute TTL, single-use tracking, and automatic cleanup;
  - Authoritative Hub Server Endpoints (`src/registry/server.mjs`):
    - `POST /hub/pairing/generate-code` (requires authenticated operator session; returns code, TTL, and verified TLS QR link);
    - `POST /hub/pairing/verify` (accepts pairing code, exchanges for authenticated session, enforces IP rate limiting);
    - `GET /hub/pairing/status` (reports network route state, verified TLS host, and pairing activity);
  - SSE Event Stream: `GET /hub/pairing/events` providing real-time notification (`device-connected`, `node-paired`) to active desktop settings sessions;
  - Audit logging of pairing generation, verification, and revocation.
- **Gate 2 Review**: Independent review of pairing endpoints, cryptographic safety, and audit logs.

### Stage 3: DSH Native Settings UI Injection & Client Pairing Workflow (Gate B)
- **Objective**: Implement the client-side UI bundle injecting Orbit controls into DSH's native Settings menu via UI slots.
- **Scope & Verified TLS Enforcement**:
  - `src/plugin/client.mjs` (bundled via esbuild to `lib/client.js`):
    - Injecting into `slots.inject('settings.section', ...)` to render an "Orbit Remote & Fleet" section in DSH Settings;
    - React UI component: `OrbitSettingsSection` communicating with Hub control API over verified TLS route authority (`https://...`);
    - Inline SVG QR Code (`generateQrSvg`): Encodes strictly verified TLS URLs (e.g. `https://<hub-domain>/auth?token=...`); raw unencrypted `http://` URLs are strictly prohibited;
    - Display features: 6-digit large text display, countdown timer, refresh button, network route diagnostics;
    - Device and Node visibility: List active operator sessions and enrolled nodes with reachability status and single-click revocation;
  - Integration tests for UI slot injection and DOM rendering.
- **Gate B Review**: UI and end-to-end integration review.

### Stage 4: Resilience, Rate Limiting, Brute-Force Containment & Zero-Leak Security (Gate 3)

## 4. M36 Acceptance Matrix Definition (Canonical 36 Fields)

The M36 matrix inherits all 32 fields from RFC-0015 (M32) and introduces 4 new fields dedicated to DSH plugin registration and QR pairing:

| Field Index | Field Identifier | Minimum Evidence | Requirement & Verification Standard |
|:---:|:---|:---:|:---|
| 1–32 | *(Inherited RFC-0015 M32 Fields)* | *Mixed* | Inherits complete M32 baseline (15 automated fields + 17 mounted fields). |
| **33** | `dshPluginCordisRegistration` | **automated** | Plugin successfully declares Cordis manifest, loads via `apply(ctx)`, and exposes registered endpoints. |
| **34** | `dshSettingsNamespacePersistence` | **automated** | Configuration read, watched, and mutated via DSH `settings` service under `~/.dsh/settings.yaml` namespace `dsh-orbit`. |
| **35** | `dshNativeSettingsSlotInjection` | **mounted** | DSH desktop settings UI renders "Orbit" section via `slots.inject('settings.section')` with live status. |
| **36** | `qrPairingBootstrapAndExchange` | **mounted** | Ephemeral 6-digit code generates inline SVG QR, mobile browser scans and verifies, establishing session with SSE update. |

**Matrix Partitioning Invariant**: Exactly **17 automated fields** (15 + 2) and **19 mounted fields** (17 + 2), totaling **36 canonical fields**.

## 6. Stop-Work Matrix

| Symptom | Severity | Required Action |
|:---|:---:|:---|
| Request Host/Origin rewritten to 127.0.0.1 (virtual loopback) | Blocker | **STOP**. Prohibit virtual loopback washing; enforce genuine authority boundaries. |
| Browser session conflated with DSH node machine identity | Critical | **STOP**. Enforce strict separation between operator sessions and node identities. |
| Unencrypted HTTP used across public/external network | Critical | **STOP**. Require verified TLS (`https://`) for all remote transport and QR links. |
| Pairing code valid for > 5 minutes or reusable | Critical | **STOP**. Enforce single-use disposable codes with <= 300s TTL. |
