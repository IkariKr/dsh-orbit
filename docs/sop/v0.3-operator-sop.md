# DSH Orbit v0.3 operator SOP

This runbook covers the implemented Registry MVP only. The stage authority is
[`v0.3-registry-mvp-multistage-sop.md`](v0.3-registry-mvp-multistage-sop.md);
RFC contracts remain frozen.

## Before starting

1. Put the Registry database on persistent storage and protect it.
2. Configure the Hub with `DSH_ORBIT_HUB_DB`, loopback `DSH_ORBIT_HUB_LISTEN`,
   the gateway assertion or strict LAN boundary, and the trusted external
   scheme. See [`../configuration-reference.md`](../configuration-reference.md).
3. Configure the gateway for TLS and authentication. It must inject the Hub
   assertion and operator principal, preserve browser origin/fetch metadata,
   and refuse `/api/v1/*`.
4. Keep the machine-ingress sidecar private. Never publish the machine port.

## Start and stop

Start the Hub with:

```sh
node bin/dsh-orbit-hub.mjs
```

Start an enrolled Node with:

```sh
node bin/dsh-orbit-node.mjs run
```

The Hub performs maintenance once at startup and every 30 seconds. Stop both
processes with `SIGTERM`/the service manager and wait for the process to close
before moving or restoring the database. Do not kill unrelated processes by
name or pattern.

## Browser session and tokens

1. Open the gateway URL and complete gateway authentication.
2. The Hub creates a management session and CSRF token.
3. Mint an enrollment token only when ready to hand it to the intended Node;
   the plaintext is shown once and is not recoverable from the token list.
4. Use the token list for status (`active`, `expired`, or `consumed`), not for
   plaintext recovery.
5. End the session when finished.

## Node operations

Follow [`v0.3-node-enrollment-sop.md`](v0.3-node-enrollment-sop.md) for
initial enrollment, reports, rotation, and reenrollment. A Node never
automatically changes identity or reenrolls after revocation.

## Health interpretation

Treat these dimensions independently:

- `registryContact`: heartbeat authority; `fresh` → `stale` after missed beats
  → `lost` after 24 hours, with `contact-lost`.
- `authenticated`: machine authentication state.
- `dshHealthy` and `orbitCompatible`: compatibility evidence dimensions.
- `reachable`: remains the explicit `unknown` value in v0.3.
- `capabilities`: active capabilities; withheld when evidence is stale.
- `capabilityEvidence`: the last stored derived evidence.

A report does not restore `registryContact`. An authenticated heartbeat restores
fresh contact and clears `contact-lost`.

## Delete and reenroll

Delete is a destructive operator action. Use the confirmation flow, provide a
reason, and retain the generated 32-character lowercase request ID for an
idempotent retry. A deleted Node remains a tombstone. Mint a tombstone-bound
reenrollment token only after verifying the intended Node ID, then perform an
explicit `node reenroll` operation. Never create a replacement Node merely to
recover a tombstone.

## Restart and recovery

- Hub restart: use the same persistent database; verify the listening message,
  health endpoint, Node identity, reports, and audit/session state.
- Node restart: use the same state file and Hub URL; verify the same node ID and
  key ID. Pending rotation recovery is automatic through commit detection.
- A pending reenrollment is replayed explicitly with the same operator token;
  it is never triggered automatically.

## Backup and restore

Use the dedicated [`v0.3-registry-backup-restore-sop.md`](v0.3-registry-backup-restore-sop.md).
The generic DSH snapshot/rollback contract is separate.

## Evidence and maintenance

For a release or incident record, capture exact Orbit revision, schema version,
Node IDs (not private keys), health transitions, backup method, restore result,
and cleanup. Do not change production thresholds for a drill. Use
[`docs/troubleshooting.md`](../troubleshooting.md) for failures.
