# DSH Orbit v0.4 Production Promotion & Rollback Plan

This plan documents the preflight requirements, cutover steps, and verified rollback procedures for promoting DSH Orbit v0.4 to production.

> **Execution Constraint**: This document defines the operational plan only. Production cutover is **strictly prohibited** during Stage 8 and may only occur after formal Review Gate approval.

## 1. Current State vs Target Topology

- **Current Production State**:
  - Single DSH instance accessed directly via `https://dsh.ikarikore.top/`.
  - Static reverse proxy forwarding to local DSH container.
- **v0.4 Target Topology**:
  - **Management Authority**: `https://orbit-admin.ikarikore.top/` (Hub management UI and `/hub/*` surface; outside the route namespace).
  - **Selector Apex**: `https://dsh.ikarikore.top/` (serves the Orbit Hub Endpoint Selector UI).
  - **Node Route Authorities**: `https://n-<nodeId>.dsh.ikarikore.top/` (dedicated subdomain per enrolled node).
  - **Reverse Proxy**: TLS for `orbit-admin.ikarikore.top`, wildcard TLS on `*.dsh.ikarikore.top`, and `dsh.ikarikore.top`, forwarding browser traffic to Hub loopback with the complete `Host:port` preserved and gateway assertion/principal injected on management and selector surfaces.

## 2. Preflight Checklist

1. **Authority DNS**: Verify `orbit-admin.ikarikore.top`, `dsh.ikarikore.top`, and `*.dsh.ikarikore.top` resolve to the appropriate gateway/private ingress endpoints.
2. **Wildcard TLS Certificate**: Ensure outer gateway certificates cover `orbit-admin.ikarikore.top`, `dsh.ikarikore.top`, and `*.dsh.ikarikore.top`.
3. **Hub Authority Configuration**: Set `DSH_ORBIT_HUB_ROUTE_DOMAIN=dsh.ikarikore.top` and `DSH_ORBIT_HUB_MANAGEMENT_AUTHORITY=orbit-admin.ikarikore.top`; verify management is outside the complete route namespace.
4. **Hub Database**: Clean migration to schema version 5 verified via `VACUUM INTO` pre-flight backup.
5. **Node RouteIngress**: Ensure node endpoints are up, certificates configured, and reachable from the Hub host.
6. **Private CA Trust**: If nodes use private-CA TLS, configure `DSH_ORBIT_HUB_CA_CERT` before starting Hub.

## 3. Promotion & Cutover Sequence

1. **Step 1: Backup Hub Database**
   Execute atomic SQLite backup:
   ```sh
   DSH_ORBIT_REGISTRY_SOURCE=/data/orbit/registry.db \
   DSH_ORBIT_REGISTRY_BACKUP=/backups/registry-pre-cutover.db \
   node --input-type=module scripts/backup-runner.mjs
   ```
2. **Step 2: Deploy v0.4 Hub & Nodes**
   - Start Hub with `DSH_ORBIT_HUB_ROUTE_DOMAIN=dsh.ikarikore.top` and `DSH_ORBIT_HUB_MANAGEMENT_AUTHORITY=orbit-admin.ikarikore.top`.
   - Start enrolled Nodes with `RouteIngress` enabled and private machine URLs configured independently from browser authorities.
3. **Step 3: Update Gateway Configuration**
   - Update reverse proxy (e.g., Caddy/Nginx) to proxy `orbit-admin.ikarikore.top`, `dsh.ikarikore.top`, and `*.dsh.ikarikore.top` to Hub loopback port (default 5445).
   - Ensure the complete `Host:port`, browser Origin, gateway assertion/principal, and WebSocket upgrade headers are handled according to Orbit's authority policy; forwarded headers are not authority inputs.
4. **Step 4: Verification & Acceptance Window**
   - Verify `https://dsh.ikarikore.top/` loads the Selector UI.
   - Verify eligible nodes show green badges.
   - Click each node: verify navigation to `https://n-<nodeId>.dsh.ikarikore.top/` loads DSH and WebSocket connects.
   - Verify host-only cookies do not cross domain boundaries.

## 4. Rollback Contract & Procedures

If critical defects or routing failures occur during the monitoring window, execute rollback immediately.

### Rollback Contract
- **No Identity Destruction**: Rollback occurs at the **gateway and DNS layer only**.
- **Preserve Registry State**: Do NOT clear the database, do NOT delete nodes, do NOT re-enroll nodes, and do NOT alter node IDs.

### Rollback Steps
1. **Revert Gateway Configuration**:
   - Revert Caddy/Nginx config to point `dsh.ikarikore.top` back to the legacy single DSH container.
   - Reload gateway service (`caddy reload` or `nginx -s reload`).
2. **Verify Legacy Service**:
   - Verify `https://dsh.ikarikore.top/` connects to the original single-node DSH interface.
3. **Post-Rollback Analysis**:
   - Leave Orbit Hub and Node processes running in isolation for diagnostic log retrieval.
