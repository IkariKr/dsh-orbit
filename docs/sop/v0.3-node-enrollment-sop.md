# DSH Orbit v0.3 Node enrollment SOP

This procedure uses the frozen `ORBIT-MACHINE-V1` and
`ORBIT-REENROLL-V1` contracts. The Node private key stays in the Node state
file and never leaves the Node.

## Prepare the Node

1. Create a dedicated state path and protect it at POSIX mode `0600`.
2. Set `DSH_ORBIT_HUB_URL` to the private Hub/machine-ingress URL.
3. Set the runtime identity variables for the installed Orbit and DSH versions.
4. Do not put plaintext tokens or private keys in scripts, logs, or evidence.

## Initial enrollment

An operator mints an `enroll` token through the authenticated browser surface.
On the intended Node, run:

```sh
DSH_ORBIT_NODE_STATE=/path/node-state.json \
DSH_ORBIT_HUB_URL=http://private-registry.example/ \
DSH_ORBIT_ENROLL_TOKEN=<one-time-token> \
node bin/dsh-orbit-node.mjs enroll
```

The command prints the Node ID and key ID. The token is not stored. Confirm the
state file is `active`, then start the heartbeat loop:

```sh
node bin/dsh-orbit-node.mjs run
```

## Reports and status

Upload a validated compatibility report with:

```sh
DSH_ORBIT_REPORT_FILE=/path/report.json node bin/dsh-orbit-node.mjs upload-report
```

Use `status` for local identity and lifecycle state, and `doctor` for
non-mutating local integrity and reachability checks. A report contributes
compatibility evidence and capabilities; only an authenticated heartbeat
controls Registry contact freshness.

## Restart

Restart with the same state path and exactly the same canonical Hub URL. The
Node keeps its node ID and current key. A pending rotation is resolved by
commit detection; restart never creates a third rotation key and never
automatically reenrolls a revoked Node.

## Credential rotation

Run:

```sh
node bin/dsh-orbit-node.mjs rotate
```

The intent is persisted before the request. If the response is uncertain, the
same pending key is probed and either promoted after commit detection or
resubmitted under the old key. Do not delete the state file during recovery.

## Revocation and reenrollment

A Hub delete changes the Node to a tombstone and the Node becomes locally
`revoked` after an authenticated denial. Reenrollment is an explicit operator
workflow:

```sh
DSH_ORBIT_REENROLL_TOKEN=<tombstone-bound-token> \
node bin/dsh-orbit-node.mjs reenroll
```

Retry with the same token if the response is uncertain. The persisted pending
request and key are replayed exactly, the original node ID is restored, and no
new node ID is minted. A revoked Node must not reenroll automatically.

## Failure handling

- `unknown-key`, timestamp, replay, rate-limit, and 5xx outcomes do not by
  themselves persist `revoked`.
- A Hub binding mismatch fails closed.
- A corrupt or permissive state file fails closed; do not edit it in place.
- Preserve the state file and consult [`../troubleshooting.md`](../troubleshooting.md)
  before retrying an identity-changing operation.

See [`../node-registry-client.md`](../node-registry-client.md) for the complete
state schema and [`../configuration-reference.md`](../configuration-reference.md)
for environment variables.
