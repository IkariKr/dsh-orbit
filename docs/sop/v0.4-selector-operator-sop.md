# DSH Orbit v0.4 Selector & Routing Operator SOP

This SOP defines the operational procedures for managing multi-node routing, route targets, and browser selection in DSH Orbit v0.4.

## 1. Prerequisites & Routing Architecture

- **Selector Apex**: The operator and end-users access the selector at the route domain apex (e.g., `https://dsh.example.com/`).
- **Node Route Authority**: Enrolled nodes are accessible at deterministic host-isolated subdomains: `https://n-<nodeId>.<routeDomain>/`.
- **Wildcard DNS & TLS**: The outer reverse proxy must terminate wildcard HTTPS (`*.dsh.example.com`), preserve incoming `Host` headers, and forward traffic to the loopback Hub listener.
- **Server-Reachable Only**: All nodes in v0.4 must be directly reachable from the Hub over IP/TLS.
  > **Notice**: Reverse-connected nodes and NAT traversal are not supported in v0.4 and remain a v0.5 scope.

## 2. Viewing Node Eligibility

When an operator accesses the Selector UI at `/`:
1. The Hub queries the Registry for active nodes and derives eligibility.
2. A node is marked **Eligible** if and only if all five conditions are satisfied:
   - `state === 'active'`
   - `authenticated === 'ok'`
   - `dshHealthy === 'ok'`
   - `orbitCompatible === 'pass'`
   - `reachable === 'ok'`
3. Clicking an eligible node navigates the browser to its dedicated `n-<nodeId>.<routeDomain>` authority.
4. If a node is ineligible, an informative badge is displayed, and navigation is blocked.

## 3. Managing Route Targets

Route targets are mutable origin URLs (HTTP or HTTPS) pointing to the node's `RouteIngress`.

### Setting / Updating a Route Target
Using the Hub management API:
```sh
curl -X POST http://127.0.0.1:5445/hub/nodes/<nodeId>/route-target \
  -H "X-DSH-Authenticated-Proxy: <gateway-secret>" \
  -H "Content-Type: application/json" \
  -d '{"routeTarget": "https://node-host.example:50081"}'
```
- The Hub immediately initiates a route-readiness probe to `GET /_orbit/route-ready`.
- On receiving HTTP 200 with `{ "ready": true, "nodeId": "<nodeId>" }`, `reachable` becomes `ok`.

### Removing a Route Target
Setting an empty route target removes it:
```sh
curl -X DELETE http://127.0.0.1:5445/hub/nodes/<nodeId>/route-target \
  -H "X-DSH-Authenticated-Proxy: <gateway-secret>"
```
- The node immediately transitions to `reachable = 'unknown'`, removing it from eligibility.

## 4. No Silent Failover Guarantee

- Orbit enforces strict host and node isolation.
- If an active node experiences an outage (DSH process loss or network timeout), requests return 502/504 and the node becomes `unreachable`.
- **Traffic is NEVER silently redirected to another node.** The operator must explicitly navigate to an alternate node via the selector apex.

## 5. Node Deletion and Re-enrollment

### Deleting a Node
```sh
curl -X DELETE http://127.0.0.1:5445/hub/nodes/<nodeId> \
  -H "X-DSH-Authenticated-Proxy: <gateway-secret>" \
  -H "Content-Type: application/json" \
  -d '{"requestId": "<32-hex-id>", "reason": "decommission"}'
```
- State transitions to `tombstoned`.
- All associated Hub route keys in `hub_route_keys` are immediately marked `revoked`.
- Bookmarks to `https://n-<nodeId>.<routeDomain>/` fail closed with 404.

### Re-enrolling a Tombstoned Node
To re-activate a tombstoned node:
1. Mint a tombstone-bound re-enrollment token from the Hub:
   ```sh
   curl -X POST http://127.0.0.1:5445/hub/nodes/<nodeId>/reenroll \
     -H "X-DSH-Authenticated-Proxy: <gateway-secret>"
   ```
2. On the node host, run:
   ```sh
   DSH_ORBIT_REENROLL_TOKEN='<token>' node bin/dsh-orbit-node.mjs reenroll
   ```
3. The node retains its original `nodeId`, while the Hub provisions a brand new Hub route identity.
4. Old keys from the deleted era remain permanently revoked.
