# DSH Orbit v0.3 Registry backup and restore SOP

This runbook covers the Registry SQLite database. It is distinct from the
generic downstream DSH snapshot contract in [`../snapshot-rollback.md`](../snapshot-rollback.md).

## CLI boundary

There is no production backup or restore CLI. Do not add a runtime subcommand or
invoke a hypothetical `registry backup`/`registry restore` command. `npm run
stage7:drill` runs only the isolated Stage 7 evidence drill; it is not a
production backup/restore operation or a substitute for this runbook.

The production operations below call the reviewed Registry library primitives
from the repository root with `node --input-type=module`. Replace the paths with
the mounted production paths before running them. The examples print only
redacted basenames and non-secret inspection fields.

## Backup prerequisites

- Keep the Hub and Registry writer healthy.
- Choose a new destination; an existing destination is never overwritten.
- Keep the source database on persistent storage.
- Do not copy a live `.db` file by itself while WAL may contain committed state.

The Registry backup primitive uses SQLite `VACUUM INTO` on the open WAL-backed
connection. It creates a standalone image that is inspected for schema,
`integrity_check`, `foreign_key_check`, journal mode, row counts, and a
non-secret business-state digest.

## Temporary and final-file privacy

Orbit exclusively creates the temporary `.partial` path before invoking
`VACUUM INTO`. On POSIX it is mode `0600` from creation, independent of the
process umask. Orbit retains final chmod enforcement after SQLite finishes and
after publication. Registry DB, backup, and restore images are not intended to
be group/other-readable. Windows has no equivalent POSIX mode-bit assertion.

**v0.4 forward boundary:** the v0.3 schema contains no Hub→Node route private
keys. Proposed RFC-0008 rev. 5 adds per-node Hub route private keys to durable
Registry state, so every v0.4 live DB/WAL, temporary backup, standalone backup,
restore staging image, and quarantine copy is classified as **secret-bearing**.
The same backup primitive remains appropriate, but v0.4 release work must keep
least-privilege file protection, treat backup storage as credential storage,
and ensure inspection/evidence never prints private keys or digests derived
only from private-key bytes. Application-level KMS/envelope encryption is not
a v0.4 requirement; host/volume encryption remains an operator deployment
control.

## Backup procedure

From the repository root, open the source connection, run the backup, and close
the connection even when the operation fails:

```sh
DSH_ORBIT_REGISTRY_SOURCE=/data/orbit/registry.db \
DSH_ORBIT_REGISTRY_BACKUP=/backups/registry-20260902T000000Z.db \
node --input-type=module <<'NODE'
import { openRegistryDatabase } from "./src/registry/sqlite.mjs";
import { backupRegistryDatabase, inspectRegistryDatabase } from "./src/registry/backup.mjs";

const sourcePath = process.env.DSH_ORBIT_REGISTRY_SOURCE;
const destinationPath = process.env.DSH_ORBIT_REGISTRY_BACKUP;
if (!sourcePath || !destinationPath) {
  throw new Error("set DSH_ORBIT_REGISTRY_SOURCE and DSH_ORBIT_REGISTRY_BACKUP");
}
const db = openRegistryDatabase(sourcePath);
try {
  const result = await backupRegistryDatabase({ db, sourcePath, destinationPath });
  const inspection = inspectRegistryDatabase(destinationPath);
  console.log(JSON.stringify({
    method: result.method,
    paths: { source: "<redacted>", backup: "<redacted>" },
    inspection: {
      schemaVersion: inspection.schemaVersion,
      journalMode: inspection.journalMode,
      integrityCheck: inspection.integrityCheck,
      foreignKeyViolations: inspection.foreignKeyViolations,
      rowCounts: inspection.rowCounts,
      stateDigest: inspection.stateDigest,
    },
    quarantine: null,
    sidecars: {
      sourceWalPresent: result.sourceWalPresent,
      sourceShmPresent: result.sourceShmPresent,
      backupWalPresent: result.backupWalPresent,
      backupShmPresent: result.backupShmPresent,
    },
  }, null, 2));
} finally {
  db.close();
}
NODE
```

Before accepting the result, verify:

- method is `sqlite-vacuum-into`;
- source and standalone backup integrity/FK checks pass;
- the backup schema is current;
- backup has no `-wal` or `-shm` sidecars;
- the destination is new and the source was not replaced.

The returned source-before/source-after records allow a moving source to be
reported without treating a concurrent business write as backup corruption.

## Restore procedure

1. Stop the Hub and every Registry writer.
2. Confirm `writersQuiesced: true` in the reviewed restore invocation.
3. Validate the backup image before publication.
4. Copy it to a restore staging path and validate the staged image.
5. Quarantine the target database and stale target `-wal`/`-shm` sidecars.
6. Atomically rename the staged image to the target path.
7. Apply final file protection and inspect the published target.
8. Restart the Hub and verify schema, integrity, Node identities, health, and
   expected reports/events/audit state.

From the repository root, with the Hub and all writers stopped, restore with
`writersQuiesced: true`, then reopen and inspect the published target. The
verification connection is always closed in `finally`:

```sh
DSH_ORBIT_REGISTRY_BACKUP=/backups/registry-20260902T000000Z.db \
DSH_ORBIT_REGISTRY_TARGET=/data/orbit/registry.db \
node --input-type=module <<'NODE'
import { openRegistryDatabase } from "./src/registry/sqlite.mjs";
import { inspectRegistryDatabase, restoreRegistryDatabase } from "./src/registry/backup.mjs";

const backupPath = process.env.DSH_ORBIT_REGISTRY_BACKUP;
const targetPath = process.env.DSH_ORBIT_REGISTRY_TARGET;
if (!backupPath || !targetPath) {
  throw new Error("set DSH_ORBIT_REGISTRY_BACKUP and DSH_ORBIT_REGISTRY_TARGET");
}
const result = await restoreRegistryDatabase({ backupPath, targetPath, writersQuiesced: true });
let verification;
const verificationDb = openRegistryDatabase(targetPath);
try {
  verification = inspectRegistryDatabase(targetPath);
} finally {
  verificationDb.close();
}
console.log(JSON.stringify({
  method: result.method,
  paths: { backup: "<redacted>", target: "<redacted>" },
  inspection: {
    schemaVersion: verification.schemaVersion,
    journalMode: verification.journalMode,
    integrityCheck: verification.integrityCheck,
    foreignKeyViolations: verification.foreignKeyViolations,
    rowCounts: verification.rowCounts,
    stateDigest: verification.stateDigest,
  },
  quarantine: {
    path: result.quarantinePath ? "<redacted>" : null,
    quarantinedSidecars: result.quarantinedSidecars,
  },
}, null, 2));
NODE
```

A failed validation or publication restores the previous target where
possible; the quarantine is retained for diagnosis. Never pair a restored
standalone image with an old WAL/SHM sidecar.

## Verification and rollback

Use `inspectRegistryDatabase()` after backup and after restore. Compare the
non-secret state digest and row counts. If restoration is part of an upgrade,
follow the generic snapshot manifest and image rollback requirements in
[`../snapshot-rollback.md`](../snapshot-rollback.md); Registry restore does not
replace the downstream production snapshot contract.

See [`../troubleshooting.md`](../troubleshooting.md) for integrity failures,
writer locks, permissions, and sidecar recovery.
